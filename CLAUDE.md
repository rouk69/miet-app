# Расписание НИУ МИЭТ — бот и мини-приложение

Неофициальный проект для студентов МИЭТ. Две части поверх одних данных:

- **Telegram-бот** `@mietapp_bot` — расписание в личке, в inline-режиме
  (`@mietapp_bot` в любом чате) и кнопками прямо в сообщении;
- **мини-приложение** — веб-версия на GitHub Pages: расписание, новости,
  кружки, институты, кампус, ссылки.

Источник всего — `miet.ru`. Расписание тянется живьём, остальное собирается
скриптами в `data/app.json` и коммитится в репозиторий.

## Правила, которые легко нарушить

**Логика расписания продублирована.** `bot/schedule_api.py` и
`js/schedule.js` — порты друг друга: разбор предметов, недели цикла,
группировка по слотам. Меняешь одно — меняй второе, иначе бот и веб
покажут разное. Коды типов занятий (`lek`/`pr`/`lab`/`oth`) обязаны
совпадать.

**Пара — это слот звонков, а не запись.** У языка и физкультуры бывает
несколько подгрупп в одно время, МИЭТ отдаёт их отдельными записями с
одинаковым временем. Считать записи парами нельзя: получится «7 пар»
вместо шести. Для показа используй `slots_of()` / `slotsOf()`, а
`lessons_of()` — только там, где нужны сырые записи (например, поиск
идущей сейчас пары).

**Утренняя карточка дня** (`bot/morning.py`) приходит в 7:30 по Москве
всем, у кого выбрана группа. Под ней две кнопки: «Открыть расписание»
(ведёт в мини-приложение) и «Не присылать» — по ней бот отвечает, что
уведомления отключены, и больше не пишет. Поэтому в базе хранится
ОТКАЗ (`users.morning_off`), а не согласие: строка есть не у всех, и
пустое значение обязано означать «шлём». Уйти от рассылки должно быть
так же просто, как её получить, — одно нажатие под самим сообщением, а
не поиск настроек. Три правила: молчим в выходные и в дни без пар
(«сегодня пар нет» — приятная мелочь ровно один раз, дальше это
будильник ни о чём), и один раз в день — дата отправки лежит в
`users.morning_at`, иначе перезапуск контейнера в восемь утра обернулся
бы вторым «добрым утром».

Посмотреть на неё до утра можно маршрутом
`/api/admin/day-preview?group=…&morning=1` — с `&send=1` она ещё и
придёт в Telegram, потому что читать разметку глазами бесполезно.

Вид у неё тот же, что у обычной карточки расписания: таблица, окна,
премиум-эмодзи. Отдельного оформления нет намеренно — своё расписание
человек должен узнавать с первого взгляда. Отправка передаётся в модуль
снаружи (`run_in_background(send_rich, send_plain)`): сам он про
Telegram не знает, иначе его нельзя было бы прогнать в проверках.

**Что рисует бот, видно снаружи**: `/api/admin/day-preview?group=…`
отдаёт карточку дня — текстом и разметкой, вместе с посчитанными
окнами. Иначе проверить рендер можно было только написав боту и
посмотрев глазами, а половина правок расписания живёт как раз в тексте
карточки.

**Окно между парами считается по номерам слотов**, а не по времени:
дырка в нумерации (после второй сразу пятая) и есть окно, а время
берётся с краёв — конец предыдущей пары, начало следующей. Расчёт
продублирован, как и остальная логика расписания: `gaps_of()` в
`bot/schedule_api.py` и `gapsOf()` в `js/schedule.js` — порты друг
друга. Показывается окно отдельной строкой между парами: студент
планирует день промежутками («успею доехать?»), и прятать это в хвост
предыдущей строки нельзя.

**Цикл четырёхнедельный.** Неделя считается от начала семестра
(`semester_start`). Пользователь может сдвинуть счёт через `/shift`, если
у деканата отсчёт другой; сдвиг привязан к семестру и сбрасывается при
его смене.

**У бота три уровня отрисовки с откатами.** Rich-сообщения (таблицы,
кнопки в тексте) → обычные сообщения с цитатами; премиум-эмодзи →
обычные. Отказ Telegram запоминается в `_rich` и `_custom_emoji`, чтобы
не дёргать сервер впустую. Новую разметку добавляй в оба варианта.

## Ограничения Telegram, о которые уже спотыкались

- `callback_data` — максимум 64 байта. Поэтому группа кодируется прямо в
  неё: кнопки под вставленной в чужой чат карточкой работают у любого,
  кто нажмёт, без серверной сессии.
- Кнопки `web_app` **запрещены** в inline-сообщениях — Telegram отклоняет
  весь `answerInlineQuery`, а не игнорирует кнопку. В inline передавай
  `webapp=False`.
- Опрашивать Telegram может только **один** экземпляр бота. Второй
  получает `409 Conflict`. Локальный бот и облачный одновременно не живут.
- В `start`-параметре диплинка разрешены только `[A-Za-z0-9_-]`, поэтому
  кириллические группы кодируются base64url (`keyboards.encode_group`).
- Сообщение — не длиннее 4096 символов, `render.clamp()` подрезает.
- Премиум-эмодзи во вставленных сообщениях требуют имени, купленного на
  Fragment. Заранее это не проверить — пробуем и запоминаем отказ.

## Серверная часть и админка

**Приложение раздаёт сервер бота, а не GitHub Pages.** Pages удобен
ровно до тех пор, пока доступен: у части операторов соединение к
`github.io` рвётся (`ERR_CONNECTION_CLOSED`), и человек видит не
приложение, а ошибку загрузки. Сервер бота при этом отвечает — через
него идут лента, ОРИОКС и расписание, — поэтому статику отдаёт он:
`api.static_file()`, каталоги `css`, `js`, `fonts`, `img`, `data` плюс
`index.html` и `webapp.version`. Всё прочее — 404, даже если файл в
репозитории есть; на `.env`, базу, код бота и `tools/` стоят отдельные
проверки. Адрес приложения считает `webapp.app_url()` — одно место на кнопку
меню, клавиатуры и утреннюю рассылку: разъехавшись, они вели бы на
разные домены. По умолчанию это свой сервер, переопределяется
переменной `APP_URL`; на `github.io` не ведём даже по просьбе
переменной — именно от него и уходили. Pages остался зеркалом, пуш в
`origin` никуда не делся.

Мини-приложение статично, поэтому всё, что нужно помнить между
устройствами, живёт в боте: `bot/api.py` поднимает HTTP-сервер отдельным
потоком в том же процессе. Отдельного сервиса нет намеренно — база одна
(`users.db` в `DATA_DIR`), а две программы, пишущие в одну SQLite на
сетевом томе, дерутся за блокировки.

**Соединение с базой одно на процесс** (`db.Shared`). Соблазн сделать
его на поток тут смертельный: `ThreadingHTTPServer` заводит поток на
каждый запрос, и каждое новое соединение прогоняло всю схему — два десятка
DDL под блокировкой записи. Соседние запросы упирались в `busy_timeout`
и отваливались ровно через десять секунд; снаружи это выглядело как
«лента иногда не грузится». Отсюда же `isolation_level=None`: с общим
соединением незакрытая транзакция одного потока подхватывала бы записи
другого. Запросы возвращают `db.Rows` — строки вычитываются под замком,
курсор наружу не отдаётся, потому что его итерация — это обращение к базе
уже вне замка.

**Ответы больше 1400 байт уходят сжатыми** (gzip), а события из приложения
пишутся одной вставкой на пачку, а не запросом на штуку.

**На доске помощи ник автора виден всем.** Это единственное место, где
контакт отдаётся не по праву, а по смыслу: объявление публикуют, чтобы с
человеком связались, и скрытый ник делает раздел бессмысленным. Экран
обязан предупредить об этом ДО публикации — в редакторе стоит заметная
плашка, а не мелкий текст внизу. Спам ограничен двумя рамками:
`MAX_OPEN` открытых объявлений на человека и `PAUSE` между
публикациями. Уборка чужого — право `help_manage`.

**Поиск по-русски требует своей функции.** `LIKE` в SQLite приводит к
нижнему регистру только латиницу: «матан» не находил «Матанализ», а
«иванов» — «Иванова». В `db.Shared` зарегистрирована `lower_ru`;
любой новый поиск по русскому тексту обязан идти через неё. Индекс на
такой функции не работает, но таблицы здесь маленькие.

**Права проверяет только сервер.** Кнопка админки в профиле спрятана от
посторонних, но это украшение: маршрут можно открыть и руками, поэтому
каждый `/api/admin/*` спрашивает роль заново. Никогда не переносить
проверку в клиент.

**Кто ты — говорит подпись, а не запрос.** Каждый вызов несёт заголовок
`X-Init-Data` — строку `Telegram.WebApp.initData`, проверяемую HMAC на
токене бота (`bot/auth.py`). Ни кук, ни сессий, ни собственных токенов.
Отсюда же следует, что вне Telegram API не работает вовсе, и приложение
обязано это переживать: без сервера оно должно оставаться рабочим, просто
без учёта и админки.

**Первый ключ — только из окружения.** Полные админы перечислены в
`ADMIN_IDS`; их роль не хранится в базе, её нельзя ни снять, ни
заблокировать из интерфейса. Иначе одним тапом можно закрыть себе
единственный вход. Пока переменная пуста, админка не открыта никому.

**Блокировка отбирает права, но не стирает их.** `identity()` возвращает
`perms` (что можно сейчас) и `granted` (что выдано). Тумблеры в админке
рисуются по `granted` — иначе снятие блокировки заодно стирало бы роль.

**Время в базе — UTC, показ — по Москве.** `CURRENT_TIMESTAMP` в SQLite
пишет UTC, а в облаке и на ноутбуке часовые пояса разные, поэтому все
группировки по дням делаются с `db.MSK`. Забыть про сдвиг — значит
получить сутки, которые режутся в три часа ночи.

**Что в учёт не попадает.** Тексты сообщений, поисковые запросы,
параметры экранов (какая именно новость или кружок). Пишутся только
идентификатор, открытая часть профиля Telegram и названия разделов. Это
не техническое ограничение, а решение — не расширять без нужды.

События с клиента уходят пачками (`js/api.js`), а не по одному:
переключение вкладок — самое частое действие, и запрос на каждый тап
означал бы десятки запросов в минуту с телефона.

## Лента

Одна таблица `posts` на два разных вида записей: посты, написанные
людьми, и новости, притащенные с miet.ru (`kind` их различает). Читаются
они вместе, сортируются вместе, реакции и прочтения у них общие —
разносить по таблицам значило бы дублировать всё это дважды.

**Видимость решает сервер, и только он.** Условие собрано одной строкой
`posts.VISIBLE` и подставляется во все запросы. Разойдись оно между
лентой и открытием поста — закрытый пост утёк бы по прямой ссылке. Пост
с аудиторией «эти группы» не должен доезжать до чужого клиента вообще:
спрятать карточку в интерфейсе недостаточно, ответ API читается руками.

**У полного админа слепых зон нет.** Флаг `see_all` снимает
проверку аудитории в `posts.VISIBLE`: адресные объявления пишутся в его
приложении, и не видеть их он не должен. Права на чужую анонимность это
не расширяет — она отдельным флагом `can_see_authors`.

**Два режима ленты переключаются на ходу** (`appconf.py`, вкладка
«Настройки» в админке): `posts_open` — писать могут все, а не только
с выданным правом; `posts_premoderate` — через очередь идёт КАЖДАЯ
запись, а не только анонимная. Хранятся в базе, а не в переменных
окружения: их меняют по обстановке, а перезапуск контейнера ради этого
никто делать не станет.

Премодерация не касается тех, у кого есть `posts_moderate`: отправлять
пост на одобрение самому себе бессмысленно, а очередь из собственных
записей мешает увидеть чужие.

**Анонимность выдаётся, а не берётся.** Анонимный пост встаёт в очередь
(`status='pending'`) и появляется в ленте после одобрения; до этого его
видит только автор. Право `posts_anon` разрешает публиковать анонимно
сразу — оно для тех, кому доверяешь. Подпись у такого поста одна для всех, включая владельца, — иначе в
его ленте он выглядел бы обычным, и было бы не видно, что человек писал
скрытно. А `author_id` вычищается из ответа: клиент показывает то, что
получил, и «скрытый» автор в JSON перестал бы быть скрытым. Исключение —
тот, кто разбирает жалобы: ему id приходит и показывается рядом с
подписью, потому что анонимность защищает автора от читателей, а не от
разбирательства.

**Комментарии видит тот, кому виден пост.** Отдельной проверки прав на
чтение обсуждения нет и быть не должно: сначала `posts.one()` решает,
доступен ли пост, и только потом отдаются комментарии. Написать может
любой, кто видит запись, — право на чтение и право на голос здесь одно и
то же. Удаляет свой комментарий автор, чужие — тот, кому выдано
`comments_delete`.

**Ветка ровно одна.** Ответ на ответ прикрепляется к тому же корню
(`reply_to` родителя, а не сам родитель): дерево произвольной глубины в
ленте объявлений не читается, а на телефоне не рисуется. Порядок
(«корень, его ответы, следующий корень») собирает сервер — иначе каждый
экран раскладывал бы ветки заново и однажды разложил бы иначе. Удаление
комментария уносит и ответы на него: сироты в базе никому не нужны, но и
терять их молча нельзя — ответ, потерявший корень, показывается как
обычный комментарий.

**Ник автора комментария отдаётся не всем** — только владельцу и тем,
кому выдано `comments_delete`. Остальным поле `contact` не приходит
вовсе: это не украшение интерфейса, а способ собрать список аккаунтов
всех, кто что-то написал.

Подпись комментария (должность) записывается в момент отправки и потом не
меняется: человека могут повысить или разжаловать, а «кто это сказал
тогда» меняться не должно. Пауза `COMMENT_PAUSE` придерживает очередь
одинаковых сообщений; ноль означает «не придерживать вовсе» — время в базе
с точностью до секунды, и запрос за последние ноль секунд поймал бы соседа
по той же секунде.

**Из серверной части в Telegram пишет `notify`.** Импортировать `main`
из `api` нельзя — это замкнуло бы круг, поэтому бот при старте отдаёт
свою отправку сообщений в `notify.bind()`. Без бота (в тестах) письма
просто не уходят.

**Голос и реакция — по одному на человека.** Ключ в `poll_votes` и
`post_reactions` стоит на паре (пост, человек), поэтому переголосование
заменяет строку, а не добавляет вторую. Повторный тап по своей реакции
снимает её, как в Telegram.

**Прочтение — это человек, а не открытие.** `post_reads` тоже с ключом на
пару, и счётчик отвечает на вопрос «сколько людей увидело». В приложении
отметка ставится, когда карточка реально побывала на экране
(IntersectionObserver), а не когда лента загрузилась в фоне.

**Доли в опросе считает сервер.** У клиента иначе разъезжается
округление: сумма долей даёт 99% или 101%.

**Картинки лежат в `DATA_DIR/media`**, имя — хеш содержимого. Тип
определяется по первым байтам, а не по расширению и не по слову клиента.
Раздаются они единственным маршрутом без подписи (`/media/<имя>`): в
`<img src>` заголовок `X-Init-Data` не поставить. Защита — неугадываемое
имя; текст и опрос закрытого поста остаются за проверкой прав.

**Новости бот тянет сам** (`news_feed`, раз в три часа) и кладёт в ту же
ленту. Разбор — селекторами из `tools/harvest.py`: они проверены на этом
сайте. Регулярками по странице не выходит — в текст новости попадает
меню сайта целиком. `data/app.json` остаётся архивом того, что собрано
скриптами; приложение показывает его отдельным экраном.

## Розыгрыш

Раздел, в котором люди зовут друг друга по личной ссылке, а тот, кто
привёл больше, стоит выше в таблице. Награды выдаёт владелец руками —
ни выплат, ни Stars, ни кошельков внутри бота нет и не заводится.
Поэтому задача кода не «наградить», а честно посчитать и показать, кого
награждать: `bot/raffle.py`, экран `js/screens/raffle.js`, вкладка
«Розыгрыш» в админке.

**Раздел невидим, пока его не открыли.** Флаг `raffle_on` (`appconf`)
по умолчанию выключен, и тогда раздел существует только для админов:
плитка в «Полезном» не показывается, а `/api/raffle` отвечает **404, а
не 403** — «нет такого раздела» правда для всех, кому он не открыт, а
403 сообщал бы, что раздел есть и скоро появится. Приглашения при этом
считаются с самого начала: к открытию таблица будет не пустой, а сам
розыгрыш можно пройти целиком самому. Открывается одним переключателем
в админке.

**Переход считается не по клику, а по делу.** Очко даётся, когда
пришедший **выбрал группу** — то есть начал пользоваться расписанием.
До этого он висит в «ждут группу». Считать сами переходы значило бы
мерить рассылку спама: открыть и уйти может кто угодно. Зачёт делает
`raffle.settle()`, и зовётся он из `storage.set_group` — то есть с
любого входа, хоть из бота, хоть из приложения. Смена группы потом
второго очка не даёт.

**Человек закрепляется за первым навсегда.** Строка в `raffle_invites`
заводится на приглашённого, а не на пару: второй ссылкой его не
перетянуть, иначе двое приглашающих перекидывали бы одного и того же
друг у друга, а счёт зависел бы от того, кто отправил последним.

**Накрутка ловится в два уровня, и второй решает человек.** Совсем
пустой аккаунт — без ника, без фото и без премиума — в зачёт не идёт
вовсе: так не выглядит ни один живой студент. Остальное подозрительное
(`fresh` — аккаунт заведён только что, виден по величине id; `burst` —
больше двенадцати переходов за час у одного приглашающего; `noname` —
нет ника) очко **не отменяет**, а вешает метку: она видна владельцу во
вкладке «Розыгрыш», и он снимает приглашение сам. Автомат, отбирающий
призы молча, ошибётся на живом студенте без аватарки и ничего не
сможет доказать. Ручное решение (`decide`) сильнее автоматического и
запоминается в `manual`.

**Фото профиля бот спрашивает у Telegram сам** (`get_user_profile_photos`
в `catch_invite`): в сообщении его нет, а без него пустой аккаунт
неотличим от живого студента без ника. Отказ (закрытый профиль) не
теряет приглашение — просто считаем, что фото нет.

**Метки подозрительности видит только тот, кто разбирает спорное**
(право `users_block`). Для остальных это обвинение без
разбирательства, вывешенное рядом с чужим именем в общей таблице.

**Равный счёт делит место.** Двое с пятью приглашёнными оба вторые, а
следующий за ними четвёртый. При равенстве выше тот, кто набрал счёт
раньше, — иначе порядок решала бы сортировка, то есть случай, и таблица
переставлялась бы сама собой при каждом обновлении. Из этого же
следует, что верх списка режется **по порядку, а не по месту**: пятеро
первых с одним очком иначе вырезали бы друг друга из экрана.

**Две двери для ссылки.** `t.me/<бот>?start=r_<код>` разбирает
`cmd_start` — эта работает всегда. Если включено главное мини-приложение,
тот же код приезжает в `start_param` и ловится уже клиентом
(`joinByLink` в `js/app.js` → `POST /api/raffle/join`), потому что бота
человек в этом случае мог не открывать вовсе. Код — шесть знаков из
алфавита без «0/o» и «1/l»: его читают вслух и набирают руками, когда
ссылка пришла картинкой. В ссылке не `user_id` — тот светил бы в каждом
сообщении, которое человек кидает в чат группы.

**Условия лежат в базе**, а не в переменных окружения: розыгрыш заводят
и перезаводят по обстановке, а правка переменной в панели Amvera — это
перезапуск контейнера и две минуты молчания бота. Название, подпись,
дата окончания и призы правятся во вкладке «Розыгрыш»; место приза —
это номер строки. Пустая дата означает «без срока», и «осталось N дней»
тогда не показывается вовсе, а не считается от балды.

## Справочник преподавателей

miet.ru отвечает только на вопрос «что у группы». «Где сейчас Иванов» и
«что идёт в 3105» таким API не решается: пришлось бы спрашивать сайт про
все 346 групп. Поэтому раз в сутки `bot/directory.py` делает это сам и
складывает плоский слепок в `lessons_index`, а поиск идёт по своей базе.

Обход намеренно неспешный: пауза между группами, старт через пять минут
после запуска бота. Триста сорок шесть запросов подряд к чужому сайту —
это то, за что банят, а расписание на семестр меняется редко.

Таблица пересобирается **одной транзакцией**: если сайт отвалится на
середине, лучше оставить вчерашний полный индекс, чем половину
сегодняшнего. Проверка на это есть в `test_admin`.

Лекция потока в расписании записана отдельной строкой для каждой группы —
при показе они схлопываются в одну пару со списком групп (`_slots()`).
Без этого день преподавателя выглядел бы вчетверо длиннее, чем он есть.

## ОРИОКС

Домашние задания в ОРИОКС живут не отдельной сущностью, а контрольными
мероприятиями дисциплины: `name`, `type` («Домашнее задание»,
«Лабораторная»), `week` — учебная неделя сдачи, `max_grade` и
`current_grade` (`-1` значит «не сдано»).

**Домашнее задание к следующему занятию — это объявление
дисциплины**, а не мероприятие. Преподаватель пишет его на странице
`/student/news/index?discipline_id=<id>`, и там оно лежит с датой,
автором и полным текстом («Задание к семинару», «Подготовка к ЛР №1»).
`id` берётся только из ведомости (`study_json`) — с чужим ОРИОКС
отвечает 403.

Страница уведомлений (`/notification/index`) для этого не годится:
она показывает лишь непрочитанное, и объявление исчезает оттуда,
стоит его один раз открыть. Выяснилось это дорого — разведка сама
пометила три объявления прочитанными в живом аккаунте. Уведомления
оставлены вторым источником: общих новостей института у дисциплин
нет. Источник этот бонусный, и его заминка не уносит первый: отказ
страницы уведомлений глотается, объявления дисциплин остаются
(`orioks.announcements()`). Иначе раздел «Что задали» пустел из-за
соседней страницы.

**Текста задания в ведомости нет.** Это проверено на
живом аккаунте, а не предположено: у мероприятия в API ровно пять
полей, соседние разделы отвечают 404, а в веб-версии (`/student/student`,
данные приезжают одним куском JSON прямо в разметке) полей больше, но
`date_start` и `date_end` пустые у всех 75 мероприятий. Раздел
«Домашние задания» на сайте (`/student/homework/list`) — это сдача
работ студентом, а не выдача условий преподавателем.

Что есть на самом деле — **файлы, приложенные к мероприятию** (поле
`irs` в веб-версии): условия, методички, бланки, семестровые планы. У
живого студента их 17 на 12 мероприятиях. Они приклеиваются к заданиям
в `orioks.with_materials()` по паре «дисциплина + мероприятие» и
показываются скрепкой в строке задания плюс отдельным разделом — почти
половина файлов висит не на заданиях, а на записях вроде «Ссылки на
учебные материалы», и без своего раздела их бы никто не нашёл.

Ссылки открываются в ОРИОКС, а не скачиваются к нам: файл лежит под
сессией института, и копировать чужие материалы в своё хранилище
неправильно.

**Веб-версия — это второй вход, отдельно от API.** Форма Yii2
(`POST /user/login`, поля `_csrf`, `LoginForm[login]`,
`LoginForm[password]`); при подключении пароль обменивается на cookie
сессии, которая ложится в `orioks_links.web_cookie`. Пароль и здесь не
сохраняется — проверка на всю базу гоняется в том числе после этого
входа.

Разбор веб-страницы стоит секунд, поэтому файлы держатся в памяти
процесса полчаса (`orioks._MATERIALS`).

**Сессию стирает только отказ, а не молчание.** `SessionExpired`
(пришла форма входа вместо данных) — убираем cookie; любая другая
`WebError` (ОРИОКС недоступен, страница изменилась) — оставляем, иначе
человек вводил бы пароль после каждой заминки у института. Это уже
ломалось один раз, проверка «и доступ не стирается» стоит именно из-за
этого.

**Пароль не хранится нигде.** ОРИОКС меняет логин с паролем на токен
(`GET /api/v1/auth`, Basic-авторизация), в базу (`orioks_links`)
ложится только токен. Пароль проходит через сервер один раз и не
записывается — на это есть проверка, которая перебирает ВСЕ таблицы и
столбцы базы и ищет там пароль. Если будешь трогать этот код, не сломай
её: она единственное, что стоит между «удобно» и «утекли чужие учебные
аккаунты».

**Чужие задания недоступны никому**, включая владельца: в ОРИОКС ходим
под токеном того, кто спрашивает. `see_all` тут не работает и работать
не должен.

**ОРИОКС виден не отовсюду.** С адресов вне России он рвёт TLS — та же
защита, что у miet.ru. С Amvera доступен (проверено маршрутом
`/api/admin/orioks-probe`), с машины автора — нет, поэтому проверки
подменяют `orioks._request` и в сеть не ходят.

**Сторож объявлений говорит сам** (`orioks_watch.py`). Экран «Задания»
показывает объявления тому, кто зашёл, а зашёл он обычно тогда, когда
про задание и так вспомнил. Обход раз в полтора часа сравнивает список
объявлений с тем, что человеку уже показывали (`orioks_seen`), и пишет
в личку про новое. Три правила, каждое из которых родилось из «а что,
если»:

- **Первый заход молчит.** У студента к середине семестра два десятка
  объявлений, и рассылка «нового» на пустой памяти означала бы двадцать
  сообщений подряд. Первый обход только запоминает.
- **Ночью не пишем** (окно 8:00–22:00 по Москве). Задание, выложенное в
  полночь, найдётся утром: память лежит в базе, а не в счётчике
  «последних N», и ничего не теряется.
- **Молчание института — не отказ.** Сессию стирает только
  `SessionExpired`, и тогда человеку один раз говорится, что надо войти
  заново; после этого он выпадает из обхода сам — без cookie сторожить
  нечего.

Запоминаем ДО отправки: не ушло сообщение — беда невелика, а вот
повтор каждые полтора часа человек не простит. А разведка
(`/api/admin/orioks-watch`, владельцу и только про себя) — сухой
прогон: не отправляет и не запоминает, иначе «покажи, что он видит»
съедало бы настоящее уведомление. Подписка (`notify` в
`orioks_links`) включена по умолчанию и выключается переключателем в
разделе «Задания»; отключение ОРИОКС уносит и её, и память об
объявлениях.

**Неделю в дату превращает клиент**, а не сервер: начало семестра
считается из расписания (`semesterStart`), и второй расчёт на сервере
означал бы два разных ответа на один вопрос.

**Учебная неделя начинается с понедельника.** Считать от самой даты
начала семестра нельзя: 1 сентября 2026 — вторник, и вторая неделя
съезжала на день, а её конец — на 14-е. ОРИОКС в это же время
показывал вторую неделю, начавшуюся 7-го.

**Срок — это день пары, а не конец недели.** ОРИОКС знает только
номер недели, человек живёт днями. `lessonDay()` ищет в расписании
пару нужного предмета и вида на этой неделе (лабораторную среди
лабораторных, контрольную среди практик) и показывает её день, время
и аудиторию; если пары нет — остаётся конец недели.

Предметы сопоставляются по первым двум словам длиной от пяти букв
(`subjectKey`). На живой группе П-13 сошлись все восемь: названия в
ОРИОКС и в расписании miet.ru совпадают дословно, но полагаться на
это целиком не стоит — отсюда и огрубление.

## Мини-приложение

**Вкладок ровно четыре**: Главная, Расписание, Лента, Полезное. Пятая
подпись в нижней панели уже жмётся, поэтому кружки и профиль переехали
внутрь «Полезного» — туда заходят по делу, а не постоянно. Профиль
остался в одно нажатие с главной (иконка в шапке).

**Главная показывает три ближайших дела** из ОРИОКС — тем, кто его
подключил. Разбор ведомости для этого вынесен из экрана заданий
(`flatten()`, `pendingOf()` в `screens/tasks.js`): считать сроки дважды
значило бы получить два разных ответа на один вопрос. Ответ ОРИОКС
живёт в памяти вкладки пять минут — один обход это восемь запросов к
серверу института, а на главную возвращаются по десять раз за день.
Не подключён, не ответил, нечего показать — блока просто нет: звать
подключаться на главной незачем, для этого есть плитка «Задания».

«Полезное» (`screens/useful.js`) — оглавление плитками, сгруппированное
по тому, как часто спрашивают: «Учёба» (задания, преподаватели,
аудитории, баллы, даты, помощь), потом университет, инструменты и
своё. Плитка внутри называется «Задания», а не так же, как раздел:
заголовок, повторяющий имя своей же плитки, ничего не сообщает. Кураторы живут в «Университете»: они не про мои сроки, а про
людей, к которым идут с вопросом. Цвет плитки закреплён за смыслом (учёба синяя,
справочное зелёное, деньги и жильё тёплые, инструменты фиолетовые) —
одинаковые не различались бы, пёстрые превратили бы экран в ёлку.

**Ссылки в коде проверяются отдельно.** Каталог из `data/app.json`
проверяет `links_probe.py`, а адреса, записанные прямо в экранах
(официальные каналы, справочник первокурсника, контакты студсовета),
не проверял никто — такие ссылки тихо умирают. Для них есть
`tools/check_links.py`; в обычный набор проверок он не входит, потому
что трогает чужие сайты. Гонять перед выкладкой, если правил эти экраны.

Там же список `UNVERIFIABLE`: ОРИОКС и личный кабинет рвут TLS с
внешних адресов — та же защита, из-за которой miet.ru молчит через VPN.
Считать их мёртвыми нельзя, иначе проверка станет вечно красной и её
перестанут запускать.

**Про чаты и кураторов ничего не выдумано.** Каждая ссылка открыта
руками, у телеграм-каналов сверено описание (оба заявляют себя
официальными), сведения о кураторах взяты со справочника первокурсника
и страницы студсовета. Личных контактов кураторов в приложении нет —
их нет и в источниках.

**Чего в справочных экранах нет намеренно.** Оценок из ОРИОКС: доступа к
чужому личному кабинету у приложения нет и быть не должно, поэтому
калькулятор БРС считает по тем баллам, которые человек ввёл сам. Точных
дат сессии: их каждый год объявляет университет, и выдуманная дата хуже
её отсутствия — вместо неё ссылка на официальный график.

**Эмодзи в интерфейсе не используются.** Они разные на разных телефонах и
ломают ровный вид списков. Всё рисуется SVG из `js/icons.js` (стиль
Lucide, обводка 1.75). Иконка каждой сущности проставляется при сборке
данных в `tools/icons_map.py` — добавил кружок или ссылку, добавь и
иконку. В боте эмодзи остались: там они запасной вариант для премиум-икон.

Дизайн — стиль «си» (see.tg): фон страницы `#EEF0F5`, а не белый; карточки
24px; кнопки и вкладки — pill; одна почти незаметная тень; шрифт Manrope,
почти весь текст жирнее привычного. Токены — в `css/tokens.css`.

Сборки нет: ES-модули грузятся браузером напрямую. Правку видно после
перезагрузки страницы.

## Внешний вид

**Значок предмета** (`js/subjects.js`). Расписание — это восемь строк,
отличающихся только текстом, и ищут в нём обычно одно: «когда у меня
физика». Цветной значок отвечает на это без чтения. Иконки здесь свои,
а не из `icons.js`: те одноцветные и штриховые, как требует дизайн-кит,
а тут нужен цвет. Каждая собрана из полупрозрачной заливки и обводки
поверх, обе берут `currentColor`, — перекрасить значок значит поменять
один `color`, а не переписывать SVG. Цвета — те же шесть тонов
(`tone-0…5`), что у карточек заданий, и они посчитаны на контраст в
обеих темах: седьмой без `check_contrast.py` не заводить. На синей
карточке «Сейчас идёт» тон не читается, поэтому там значок белый
(`on-accent`) — предмет узнаётся по форме.

Таблица подбора одна на всё приложение: тот же предмет обязан выглядеть
одинаково и в расписании, и на главной, и в заданиях. Две таблицы
разошлись бы на первом новом предмете — раньше так и было, вторая жила
в `screens/tasks.js`. Порядок правил в ней значим, и проверен он на
живом расписании МИЭТ, а не придуман: «Командные виды спорта» уезжали к
психологии по слову «командн», «Основы управления проектами» — к праву,
потому что «прав» сидит внутри «управления», а «Основы теории
информации» не ловились правилом `информат`. Все три случая закреплены
проверками в `check_app`. Незнакомому предмету цвет считается из букв
названия — постоянный, а не случайный: иначе цвет ничего не значит.

**Имена классов не делятся между разделами.** Карточка объявления
ОРИОКС называлась так же, как карточка новости (`news-card`,
`news-title`, `news-date`), и, будучи описанной ниже в файле, молча
переопределяла её: лента новостей получала `display:flex` и обложку
сбоку. Ничего не падало — увидеть можно было только глазами.
Объявления теперь `notice-*`, а `check_modules` ругается на два блока
с одинаковым селектором. Групповой селектор (`.a img, .a-stub`) и
отдельное правило для той же цели — законны, дубль ищется по полному
тексту селектора.

**Цвет проверяется формулой, а не глазом.** Браузера в этой среде нет,
поэтому единственная честная проверка внешнего вида — контраст:
`tools/check_contrast.py` считает его по WCAG для обеих тем. Пороги:
4.5 обычному тексту, 3.5 третичному. У акцентов два цвета: `--danger`
и `--danger-text` (то же у warning и success) — сочный оранжевый
хорош плашке и полоске графика, но строку «сегодня» им набирать
нельзя, на белом это контраст 1.8.

**Тема по умолчанию — «как в Telegram».** Выбор из профиля сильнее:
его делали руками. Ставится тема до первой отрисовки — маленьким
скриптом в `index.html`, иначе тёмная успевает мигнуть белым, — и
меняется на ходу, если её переключили в самом Telegram.

**Шрифт лежит рядом.** Manrope приезжал с двух чужих доменов, а это
три круга по сети до первой правильной буквы. Восемь файлов в
`fonts/` (четыре начертания × кириллица и латиница), `unicode-range`
тот же, что отдавал Google, лицензия OFL рядом. Начертание 500 не
берём: ради одной строки оно тянуло целый файл.

**Расписание запрашивается с первой секунды**, не дожидаясь
справочника: экран всё равно попросит его первым, а так два ожидания
идут рядом. Обещание живёт в `schedule.js` (`inFlight`), поэтому
второй такой же запрос переиспользует первый, а не шлёт свой.

**Приложение берёт расписание у бота, а не у miet.ru напрямую.**
Порядок: своя копия в телефоне (сутки) → сеть → любая копия, даже
просроченная. В сети источники идут **наперегонки**: сразу запрос к
боту (`GET /api/schedule`), через 1,2 секунды — к miet.ru, берётся
первый ответивший. По очереди было хуже: молчащий бот (например, он
перезапускается после выкладки) означал восемь секунд ожидания, прежде
чем приложение вообще попробует сайт института. Сайт института
отвечает не всем и не всегда — с части мобильных сетей он недоступен
вовсе, и это выглядело как ошибка приложения; у бота же есть кеш, и он
отвечает мгновенно. Записи он отдаёт уже нормализованными, поэтому в
`_normalize()` добавлены `teacherShort` и `group`: их рисует клиент.
Кеш при этом переименован в `sched2_*` — файлы на диске Amvera
переживают выкладку, и старые отдавали бы записи без новых полей. На
всякий случай клиент и сам терпим: `teacherOf()` берёт короткое имя,
а нет его — полное.

**Просроченная копия расписания отдаётся сразу, а обновляется в
фоне.** Свежая — из кеша, старее шести часов, но моложе суток — тоже
сразу, и следом уходит фоновое обновление (`_refresh_later`). Полторы
секунды сетевого запроса человек замечает каждый раз, а расписание за
это время не меняется. Плюс прогрев: после перезапуска контейнера кеш
пуст, поэтому `warm_up()` тянет пятнадцать самых ходовых групп
(`storage.popular_groups()`) — перезапуск случается на каждой выкладке
бота, и без прогрева первый вопрос каждого упирался в сеть.

**Отказ сети не превращается в «данных нет».** Расписание меняется раз
в семестр, поэтому вчерашняя копия — то же самое расписание. Клиент
(`fetchSchedule`) при отказе отдаёт сохранённое даже просроченное, с
пометкой `stale`, и экран честно говорит, что показывает сохранённое;
бот (`schedule_api.fetch_schedule`) делает то же самое с файловым
кешем (`_cache_get(key, ttl=None)`). Ошибка остаётся только когда
показывать действительно нечего — и текст у неё человеческий, а не
«Failed to fetch».

**Справочник не решает, откроется ли приложение.** `data/app.json` —
это новости, кружки, институты, кампус и список групп; расписание с
miet.ru к нему отношения не имеет. Раньше отказ этого запроса валил
запуск, и человек видел «Данные не загрузились» вместо своих пар — а
отказ бывает на ровном месте: Pages пересобирается после выкладки и
минуту отвечает 404, телефон переключается с Wi-Fi на LTE. Теперь не
приехал — берётся копия из `localStorage`, нет копии — работаем без
справочника (`data.stale` / `data.missing`), а выбор группы честно
говорит, что списка нет.

**Адрес мини-приложения несёт метку выкладки.** Меток на файлах мало:
Telegram кеширует и саму страницу, по адресу, и держит её дольше, чем
просит HTTP — человек жмёт «Приложение» и открывает прошлую выкладку.
`tools/stamp.py` пишет общую метку в `webapp.version`, `keyboards.
webapp_link()` подставляет её в адрес (`?group=…&v=…`), а бот при
каждом запуске переставляет на этот адрес кнопку меню.

**Метку бот читает у самого приложения** (`bot/webapp.py`,
`WEBAPP_URL/webapp.version`, раз в четверть часа), а не из своего
репозитория. `/api/health` показывает обе метки: `webapp` — та, что бот считает
текущей и ставит в адрес кнопки, `webapp_on_disk` — лежащая в его
копии репозитория. Расходятся они, когда клиент выложили без выкладки
бота: это обычный случай, а не поломка.

Каждым кругом он ещё и сверяет, куда ведёт кнопка меню:
разовая установка могла не удаться (Telegram ответил «слишком часто»),
и чинить её иначе было бы некому — метка-то не менялась. Иначе каждая правка клиента требовала выкладки бота, а
выкладка перезапускает контейнер: пара минут молчания из-за правки
цвета кнопки. Пуш в `amvera` теперь нужен, только когда менялся сам
бот; клиент выкладывается в `origin`, и бот замечает это сам.

**«Не открывается, ERR_CONNECTION_CLOSED» — это оборванное соединение,
и причин у него ровно две.** Либо в эту секунду поднимался контейнер
(пока процесс не слушает порт, envoy рвёт входящие), либо до нас не
дошёл маршрут человека: Telegram в России у многих живёт через VPN, и
трафик к российскому адресу Amvera приходит из-за рубежа. Снаружи оба
случая выглядят одинаково, а лечатся по-разному, поэтому `/api/health`
отвечает ещё и про сам процесс: `uptime` — сколько секунд живём,
`starts_24h` — сколько раз поднимались за сутки, `started_at` и
`prev_start` — когда (`bot/uptime.py`, отметки в таблице `starts`,
хранятся месяц). Много запусков подряд — наша беда, контейнер падает;
запуск один и давно — оборвалось по дороге, и сервер тут ни при чём.

Причём проверено живой выкладкой 16 сентября 2026: пока контейнер
поднимался (три минуты), envoy отвечал **503**, а соединение не рвал ни
разу. То есть `ERR_CONNECTION_CLOSED` — это всегда дорога, а не наш
перезапуск; наш перезапуск человек увидел бы иначе. Счётчик запусков
всё равно нужен — он снимает этот вопрос за один запрос вместо
получаса замеров.
Подпись для этого не нужна намеренно: жалобу разбирают тогда, когда
приложение как раз и не открылось. Личного в ответе поэтому нет.

Проверять счётчиком заходов, а не ощущением: `/api/admin/days` за
вчера и позавчера. Приложение открылось у восьмидесяти человек —
значит сломалось у одного, и чинить надо не сервер.

**Запасной вход — второй путь к тому же серверу.** `mirror/worker.js`,
воркер Cloudflare, проксирует к нам всё целиком: страницу, API,
картинки. Целиком — потому что клиент спрашивает данные у того, кто его
раздал (`js/config.js` считает базу от `location.origin`, и только
зеркало на Pages отправляет вопросы на Amvera). Раньше адрес сервера
был в клиенте прибит намертво, и приложение, пришедшее запасным путём,
всё равно лезло бы за расписанием по оборванному.

Вход личный: команда `/fix` в боте, выбор хранится в
`users.entry_mirror`, а адрес под человека считает
`webapp.app_url_for()`. Тогда через воркер идут ВСЕ его кнопки —
`main.app_url()` подставляется в карточки дня, свод недели,
приветствие и утреннюю рассылку, а кнопка меню чата переставляется
лично ему (`point_menu_for`, Telegram умеет её и на один чат). Общая
кнопка меню и inline-сообщения остаются на прямом пути: они одни на
всех, и человека в них нет.

Основным воркер не делается намеренно — лишний посредник это лишняя
точка отказа и чужие лимиты. Пока `MIRROR_URL` не задана в панели
Amvera, бот запасной вход не предлагает вовсе. Сколько людей на нём
сидит, видно в сводке админки (`mirror_users`): единицы — прямой путь
здоров.

**Приложение НЕ просит полный экран.** `tg.requestFullscreen()` (Bot API
8.0) убирает полосу клиента и раскладывает «закрыть», «свернуть» и
«меню» накладными пилюлями поверх содержимого. Так было до 16 сентября
2026, и выглядело это отдельной страницей, а не перепиской с ботом:
привычных кнопок человек в шапке не находил. Теперь шапку рисует
Telegram — в ней имя бота, «свернуть» и «закрыть» там, где их ищут, как
у остальных ботов. `js/tg.js` делает обратное: `leaveFullscreen()`
выходит из режима, если клиент открыл нас развёрнутыми сам (Telegram
помнит режим в пределах сессии, и однажды развёрнутое прежней сборкой
приложение открывалось бы так и дальше). Отступы сверху и снизу
по-прежнему складываются из `safeAreaInset` и `contentSafeAreaInset` в
`--tg-safe-top`/`--tg-safe-bottom`: в обычном режиме второе почти всегда
ноль, но клиенты считают по-разному, а нижняя панель не должна садиться
на полосу жестов.

**Страница сама замечает, что она вчерашняя** (`js/fresh.js`). Метка
выкладки в адресе спасает только там, где адрес собираем мы. У главного
мини-приложения (кнопка «Открыть» в списке чатов, настраивается в
BotFather) адрес задан раз и навсегда и метки не несёт — человек открыл
бы им прошлую сборку и остался на ней, пока Telegram не забудет кеш.
Поэтому после первой отрисовки страница спрашивает `webapp.version` у
того, кто её РАЗДАЛ (не у API: у зеркала своя, отставшая копия, и
сравнивать надо с ней), и при расхождении молча перезагружается на
новую метку, сохранив параметры входа. Одна попытка на метку — иначе
страница, которая не обновилась из-за чужого кеша, крутилась бы по
кругу.

**Кнопка «Открыть» в списке чатов** — это «главное мини-приложение», и
задаётся оно ТОЛЬКО у @BotFather (/mybots → Bot Settings → Configure
Mini App → Enable Mini App), как inline-режим. Bot API его не включает,
но `getMe` о нём рассказывает полем `has_main_web_app`, поэтому
`python -m bot.setup_bot` печатает, включено оно или нет, и куда идти,
если нет. Адрес там задаётся раз и метки выкладки не несёт — за
свежесть отвечает `js/fresh.js` выше, без него человек с этой кнопки
открывал бы прошлую сборку.

**На Pages уезжает сборка, а правят исходники.** Модули без сборщика —
это тридцать два похода по сети на каждое открытие; на мобильном
интернете это секунды, проведённые со спиннером. `tools/bundle.py`
складывает те же модули в `js/bundle.js` (каждый в своей функции,
импорты — через таблицу `__mod`), `stamp.py` собирает его при каждой
выкладке, а `check_modules` сверяет: разошлась сборка с исходниками —
проверка красная. Тем же сборщиком пользуется `check_app`, то есть
сборка выполняется в движке на каждом прогоне, а не «наверное,
соберётся». В `index.html` подключена сборка; если она не выполнилась,
через две секунды подключаются исходные модули — белый экран хуже
лишнего запроса.

**Выкладка без меток не доходит.** Pages кеширует статику на десять
минут, Telegram — дольше и по своим правилам: человек открывает
приложение и видит вчерашний вид, а правка выглядит несделанной.
`tools/stamp.py` дописывает к стилям метку от содержимого и собирает в
`index.html` карту импортов, которая меняет адрес всем модулям разом.
Точка входа подключается инлайновым `import './js/app.js'` — иначе
сама она осталась бы кешированной, а её импорты обновились, и вышла бы
каша из нового и вчерашнего. Браузер без importmap (iOS до 16.4)
возьмёт всё дерево по старым адресам: не свежо, зато согласованно.
Гонять перед каждым пушем клиента, иначе правку увидишь только ты.

**Прокрутка пальцем — не нажатие.** WebView Telegram прощает небольшое
смещение и всё равно шлёт `click`: палец, ведущий главную вверх,
попадал на карточку ленты, и человека «само собой» выбрасывало на
вкладку «Лента». `guardTaps()` в `tg.js` гасит щелчок, если между
касанием и щелчком палец сдвинулся больше чем на десять пикселей и с
конца касания прошло меньше семисот миллисекунд — позже это уже мышь,
ей запрещать нечего.

**Картинка занимает место по своим пропорциям.** Стороны приезжают в
имени файла (`<хеш>-1200x800.jpg`, пишет `media.store()`), поэтому
отдельной колонки в базе нет — два числа уже лежат в самом файле.
Место под картинку резервируется заранее, иначе лента прыгает на
подгрузке; но общее соотношение «для ровного вида» ставить нельзя —
оно режет пополам скриншоты расписания, а их здесь больше, чем
фотографий. Очень высоким (снимок экрана телефона) отводится четыре
пятых ширины, и они вписываются целиком, с полями по бокам. Картинки
старше этой затеи дописывает `media.backfill()` при старте бота.

**Пустой экран объясняется картинкой, а не кружком.** `js/art.js` —
сцены на 100×100, рисованные теми же линиями, что иконки (обводка
1.75, скруглённые концы): свободный день, выходной, выбор группы,
обрыв связи. Цвет берётся из темы — обводка `currentColor`, заливки
токенами, — поэтому одна картинка живёт в обеих темах, а растровая
потребовала бы двух копий. Имена сцен сверяет `check_modules`:
опечатка рисует стопку книг вместо кружки, молча и на самом видном
месте.

**Вид занятия помечен и цветом, и значком** (доска, колба, карандаш —
`KIND_ICONS` в `screens/schedule.js`). Цвет различают не все, а лекцию
от лабораторной глаз должен отличать раньше, чем прочитает подпись.

**Первый экран не ждёт сервер.** `data/app.json` — единственное, чего
ждёт запуск. Права, группа из бота и признак блокировки приезжают
следом и меняют то, что уже нарисовано: сервер на бесплатном тарифе
после выкладки поднимается полминуты, и держать всё это время спиннер
ради прав, которые на главной не нужны, — плохая сделка.

## Данные

`data/app.json` собирается скриптами и лежит в репозитории — приложение
на GitHub Pages читает его как статику. Пересобрать:

```bash
python tools/update.py
```

Расписание в этот файл **не входит**: и бот, и веб берут его с
`miet.ru/schedule/data` вживую (CORS открыт), поэтому оно всегда свежее.

## Проверки

```bash
python -m bot.selftest      # логика, рендер, клавиатуры, лимиты — 74
python -m bot.test_flows    # обработчики целиком, Telegram подменён — 139
python -m bot.test_admin    # права, справочник, доска, ОРИОКС — 268
python -m bot.test_posts    # лента, комментарии, режимы — 141
python -m bot.test_raffle   # розыгрыш: зачёт, накрутка, видимость — 68
```

`tools/check_app.py` кроме загрузки модулей гоняет чистые функции
экрана заданий и иллюстрации (значок предмета, человеческая дата,
разбор перечня и ссылок, тип вложения, разворачивание ведомости в
список дел, сцены пустых экранов, пропорции картинок, пустой
учебный день, запасная копия расписания, окна между парами,
гонка источников, склонения и подписи дней в розыгрыше, подбор
значка предмета) — девяносто четыре проверки. Они про то, что
ломается молча: неверный значок или «6 дн. назад» вместо «вчера»
ничего не роняют, и увидеть это можно только глазами, а браузера в
этой среде нет.

`selftest` не падает, если `miet.ru` недоступен, — берёт последнее из кеша.
Все пять прогонов должны быть зелёными перед коммитом; счёт проверок
указан здесь и его надо обновлять вместе с правкой.

Тесты открывают свою базу через `db.reset_for_tests()` до первого запроса —
`db.conn()` запоминает соединение на поток, и переключить путь потом уже
нельзя. Забыть про это — значит прогоном затереть живую статистику.

**Клиент проверяется отдельно, и это обязательно.** Питоновские
прогоны не видят JavaScript вовсе, а один битый модуль роняет всё
приложение — граф импортов рушится целиком, человек получает белый экран:

    python tools/check_modules.py   # импорты, забытые имена, иконки, классы
    python tools/check_app.py       # выполняет модули в движке (нужен dukpy)
    python tools/check_contrast.py  # читаемость палитры по WCAG
    python tools/stamp.py           # метки версий, иначе правка ляжет в кеш

`check_app.py` появился после того, как приложение легло из-за двух
объявлений одного имени: `dayLabel` импортировали в модуль, где он уже
был объявлен. Ни сверка импортов, ни проверка синтаксиса по отдельным
файлам такого не видят — нужно именно выполнить сборку. Гонять обе
проверки перед каждой выкладкой клиента.

Движка JS в системе нет, поэтому `check_app.py` работает через
`dukpy` (`pip install dukpy`) с игрушечными заглушками DOM: цель не
отрисовать приложение, а дойти до конца загрузки без исключения.

`test_admin` зовёт `api.handle()` напрямую, без сокета: так проверка не
зависит ни от свободного порта, ни от системного прокси, который на машине
автора заворачивает `localhost` и отвечает 502.

## Выкладка

Мини-приложение — GitHub Pages, обновляется пушем в `origin main`.

Бот — Amvera Cloud, **пуш обязательно `main:master`**: платформа следит за
`master`, локально работа идёт в `main`.

```bash
git push amvera main:master
```

Токен только в переменных окружения панели Amvera, `.env` в `.gitignore`.
Всё, что бот пишет, должно уходить в `DATA_DIR` (в облаке `/data`) —
файлы рядом с кодом стираются при каждой выкладке. Подробности в
[DEPLOY.md](DEPLOY.md).

Две части знают друг о друге ровно в одном месте: адрес API в
`js/config.js` и переменные `ADMIN_IDS` / `ALLOW_ORIGIN` в панели Amvera.
Переехал домен бота — правится `js/config.js` и пушится в `origin main`,
иначе приложение молча останется без учёта и админки.

Частая засада: с включённым VPN `miet.ru` и `git.amvera.ru` не отвечают —
они отклоняют зарубежные адреса. TCP при этом проходит, рвётся TLS.

## Стиль

Комментарии и весь текст для пользователя — по-русски. Комментарий
объясняет, **почему** так, а не пересказывает код; если причина
неочевидна (обход ограничения Telegram, особенность данных МИЭТ) — она
должна быть записана.
