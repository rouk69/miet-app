# Расписание НИУ МИЭТ — бот и мини-приложение

Неофициальный проект для студентов МИЭТ. Две части поверх одних данных:

- **Telegram-бот** `@mietapp_bot` — расписание в личке, в inline-режиме
  (`@mietapp_bot` в любом чате) и кнопками прямо в сообщении;
- **мини-приложение** — веб-версия на GitHub Pages: расписание, новости,
  кружки, институты, кампус, ссылки.

Источник всего — `miet.ru`. Расписание тянется живьём, остальное собирается
скриптами в `data/app.json` и коммитится в репозиторий.

## Правила, которые легко нарушить

**Логика расписания продублирована.** `bot/schedule_api.py` и
`js/schedule.js` — порты друг друга: разбор предметов, недели цикла,
группировка по слотам. Меняешь одно — меняй второе, иначе бот и веб
покажут разное. Коды типов занятий (`lek`/`pr`/`lab`/`oth`) обязаны
совпадать.

**Пара — это слот звонков, а не запись.** У языка и физкультуры бывает
несколько подгрупп в одно время, МИЭТ отдаёт их отдельными записями с
одинаковым временем. Считать записи парами нельзя: получится «7 пар»
вместо шести. Для показа используй `slots_of()` / `slotsOf()`, а
`lessons_of()` — только там, где нужны сырые записи (например, поиск
идущей сейчас пары).

**Цикл четырёхнедельный.** Неделя считается от начала семестра
(`semester_start`). Пользователь может сдвинуть счёт через `/shift`, если
у деканата отсчёт другой; сдвиг привязан к семестру и сбрасывается при
его смене.

**У бота три уровня отрисовки с откатами.** Rich-сообщения (таблицы,
кнопки в тексте) → обычные сообщения с цитатами; премиум-эмодзи →
обычные. Отказ Telegram запоминается в `_rich` и `_custom_emoji`, чтобы
не дёргать сервер впустую. Новую разметку добавляй в оба варианта.

## Ограничения Telegram, о которые уже спотыкались

- `callback_data` — максимум 64 байта. Поэтому группа кодируется прямо в
  неё: кнопки под вставленной в чужой чат карточкой работают у любого,
  кто нажмёт, без серверной сессии.
- Кнопки `web_app` **запрещены** в inline-сообщениях — Telegram отклоняет
  весь `answerInlineQuery`, а не игнорирует кнопку. В inline передавай
  `webapp=False`.
- Опрашивать Telegram может только **один** экземпляр бота. Второй
  получает `409 Conflict`. Локальный бот и облачный одновременно не живут.
- В `start`-параметре диплинка разрешены только `[A-Za-z0-9_-]`, поэтому
  кириллические группы кодируются base64url (`keyboards.encode_group`).
- Сообщение — не длиннее 4096 символов, `render.clamp()` подрезает.
- Премиум-эмодзи во вставленных сообщениях требуют имени, купленного на
  Fragment. Заранее это не проверить — пробуем и запоминаем отказ.

## Серверная часть и админка

Мини-приложение на Pages статично, поэтому всё, что нужно помнить между
устройствами, живёт в боте: `bot/api.py` поднимает HTTP-сервер отдельным
потоком в том же процессе. Отдельного сервиса нет намеренно — база одна
(`users.db` в `DATA_DIR`), а две программы, пишущие в одну SQLite на
сетевом томе, дерутся за блокировки.

**Соединение с базой одно на процесс** (`db.Shared`). Соблазн сделать
его на поток тут смертельный: `ThreadingHTTPServer` заводит поток на
каждый запрос, и каждое новое соединение прогоняло всю схему — два десятка
DDL под блокировкой записи. Соседние запросы упирались в `busy_timeout`
и отваливались ровно через десять секунд; снаружи это выглядело как
«лента иногда не грузится». Отсюда же `isolation_level=None`: с общим
соединением незакрытая транзакция одного потока подхватывала бы записи
другого. Запросы возвращают `db.Rows` — строки вычитываются под замком,
курсор наружу не отдаётся, потому что его итерация — это обращение к базе
уже вне замка.

**Ответы больше 1400 байт уходят сжатыми** (gzip), а события из приложения
пишутся одной вставкой на пачку, а не запросом на штуку.

**На доске помощи ник автора виден всем.** Это единственное место, где
контакт отдаётся не по праву, а по смыслу: объявление публикуют, чтобы с
человеком связались, и скрытый ник делает раздел бессмысленным. Экран
обязан предупредить об этом ДО публикации — в редакторе стоит заметная
плашка, а не мелкий текст внизу. Спам ограничен двумя рамками:
`MAX_OPEN` открытых объявлений на человека и `PAUSE` между
публикациями. Уборка чужого — право `help_manage`.

**Поиск по-русски требует своей функции.** `LIKE` в SQLite приводит к
нижнему регистру только латиницу: «матан» не находил «Матанализ», а
«иванов» — «Иванова». В `db.Shared` зарегистрирована `lower_ru`;
любой новый поиск по русскому тексту обязан идти через неё. Индекс на
такой функции не работает, но таблицы здесь маленькие.

**Права проверяет только сервер.** Кнопка админки в профиле спрятана от
посторонних, но это украшение: маршрут можно открыть и руками, поэтому
каждый `/api/admin/*` спрашивает роль заново. Никогда не переносить
проверку в клиент.

**Кто ты — говорит подпись, а не запрос.** Каждый вызов несёт заголовок
`X-Init-Data` — строку `Telegram.WebApp.initData`, проверяемую HMAC на
токене бота (`bot/auth.py`). Ни кук, ни сессий, ни собственных токенов.
Отсюда же следует, что вне Telegram API не работает вовсе, и приложение
обязано это переживать: без сервера оно должно оставаться рабочим, просто
без учёта и админки.

**Первый ключ — только из окружения.** Полные админы перечислены в
`ADMIN_IDS`; их роль не хранится в базе, её нельзя ни снять, ни
заблокировать из интерфейса. Иначе одним тапом можно закрыть себе
единственный вход. Пока переменная пуста, админка не открыта никому.

**Блокировка отбирает права, но не стирает их.** `identity()` возвращает
`perms` (что можно сейчас) и `granted` (что выдано). Тумблеры в админке
рисуются по `granted` — иначе снятие блокировки заодно стирало бы роль.

**Время в базе — UTC, показ — по Москве.** `CURRENT_TIMESTAMP` в SQLite
пишет UTC, а в облаке и на ноутбуке часовые пояса разные, поэтому все
группировки по дням делаются с `db.MSK`. Забыть про сдвиг — значит
получить сутки, которые режутся в три часа ночи.

**Что в учёт не попадает.** Тексты сообщений, поисковые запросы,
параметры экранов (какая именно новость или кружок). Пишутся только
идентификатор, открытая часть профиля Telegram и названия разделов. Это
не техническое ограничение, а решение — не расширять без нужды.

События с клиента уходят пачками (`js/api.js`), а не по одному:
переключение вкладок — самое частое действие, и запрос на каждый тап
означал бы десятки запросов в минуту с телефона.

## Лента

Одна таблица `posts` на два разных вида записей: посты, написанные
людьми, и новости, притащенные с miet.ru (`kind` их различает). Читаются
они вместе, сортируются вместе, реакции и прочтения у них общие —
разносить по таблицам значило бы дублировать всё это дважды.

**Видимость решает сервер, и только он.** Условие собрано одной строкой
`posts.VISIBLE` и подставляется во все запросы. Разойдись оно между
лентой и открытием поста — закрытый пост утёк бы по прямой ссылке. Пост
с аудиторией «эти группы» не должен доезжать до чужого клиента вообще:
спрятать карточку в интерфейсе недостаточно, ответ API читается руками.

**У полного админа слепых зон нет.** Флаг `see_all` снимает
проверку аудитории в `posts.VISIBLE`: адресные объявления пишутся в его
приложении, и не видеть их он не должен. Права на чужую анонимность это
не расширяет — она отдельным флагом `can_see_authors`.

**Два режима ленты переключаются на ходу** (`appconf.py`, вкладка
«Настройки» в админке): `posts_open` — писать могут все, а не только
с выданным правом; `posts_premoderate` — через очередь идёт КАЖДАЯ
запись, а не только анонимная. Хранятся в базе, а не в переменных
окружения: их меняют по обстановке, а перезапуск контейнера ради этого
никто делать не станет.

Премодерация не касается тех, у кого есть `posts_moderate`: отправлять
пост на одобрение самому себе бессмысленно, а очередь из собственных
записей мешает увидеть чужие.

**Анонимность выдаётся, а не берётся.** Анонимный пост встаёт в очередь
(`status='pending'`) и появляется в ленте после одобрения; до этого его
видит только автор. Право `posts_anon` разрешает публиковать анонимно
сразу — оно для тех, кому доверяешь. Подпись у такого поста одна для всех, включая владельца, — иначе в
его ленте он выглядел бы обычным, и было бы не видно, что человек писал
скрытно. А `author_id` вычищается из ответа: клиент показывает то, что
получил, и «скрытый» автор в JSON перестал бы быть скрытым. Исключение —
тот, кто разбирает жалобы: ему id приходит и показывается рядом с
подписью, потому что анонимность защищает автора от читателей, а не от
разбирательства.

**Комментарии видит тот, кому виден пост.** Отдельной проверки прав на
чтение обсуждения нет и быть не должно: сначала `posts.one()` решает,
доступен ли пост, и только потом отдаются комментарии. Написать может
любой, кто видит запись, — право на чтение и право на голос здесь одно и
то же. Удаляет свой комментарий автор, чужие — тот, кому выдано
`comments_delete`.

**Ветка ровно одна.** Ответ на ответ прикрепляется к тому же корню
(`reply_to` родителя, а не сам родитель): дерево произвольной глубины в
ленте объявлений не читается, а на телефоне не рисуется. Порядок
(«корень, его ответы, следующий корень») собирает сервер — иначе каждый
экран раскладывал бы ветки заново и однажды разложил бы иначе. Удаление
комментария уносит и ответы на него: сироты в базе никому не нужны, но и
терять их молча нельзя — ответ, потерявший корень, показывается как
обычный комментарий.

**Ник автора комментария отдаётся не всем** — только владельцу и тем,
кому выдано `comments_delete`. Остальным поле `contact` не приходит
вовсе: это не украшение интерфейса, а способ собрать список аккаунтов
всех, кто что-то написал.

Подпись комментария (должность) записывается в момент отправки и потом не
меняется: человека могут повысить или разжаловать, а «кто это сказал
тогда» меняться не должно. Пауза `COMMENT_PAUSE` придерживает очередь
одинаковых сообщений; ноль означает «не придерживать вовсе» — время в базе
с точностью до секунды, и запрос за последние ноль секунд поймал бы соседа
по той же секунде.

**Из серверной части в Telegram пишет `notify`.** Импортировать `main`
из `api` нельзя — это замкнуло бы круг, поэтому бот при старте отдаёт
свою отправку сообщений в `notify.bind()`. Без бота (в тестах) письма
просто не уходят.

**Голос и реакция — по одному на человека.** Ключ в `poll_votes` и
`post_reactions` стоит на паре (пост, человек), поэтому переголосование
заменяет строку, а не добавляет вторую. Повторный тап по своей реакции
снимает её, как в Telegram.

**Прочтение — это человек, а не открытие.** `post_reads` тоже с ключом на
пару, и счётчик отвечает на вопрос «сколько людей увидело». В приложении
отметка ставится, когда карточка реально побывала на экране
(IntersectionObserver), а не когда лента загрузилась в фоне.

**Доли в опросе считает сервер.** У клиента иначе разъезжается
округление: сумма долей даёт 99% или 101%.

**Картинки лежат в `DATA_DIR/media`**, имя — хеш содержимого. Тип
определяется по первым байтам, а не по расширению и не по слову клиента.
Раздаются они единственным маршрутом без подписи (`/media/<имя>`): в
`<img src>` заголовок `X-Init-Data` не поставить. Защита — неугадываемое
имя; текст и опрос закрытого поста остаются за проверкой прав.

**Новости бот тянет сам** (`news_feed`, раз в три часа) и кладёт в ту же
ленту. Разбор — селекторами из `tools/harvest.py`: они проверены на этом
сайте. Регулярками по странице не выходит — в текст новости попадает
меню сайта целиком. `data/app.json` остаётся архивом того, что собрано
скриптами; приложение показывает его отдельным экраном.

## Справочник преподавателей

miet.ru отвечает только на вопрос «что у группы». «Где сейчас Иванов» и
«что идёт в 3105» таким API не решается: пришлось бы спрашивать сайт про
все 346 групп. Поэтому раз в сутки `bot/directory.py` делает это сам и
складывает плоский слепок в `lessons_index`, а поиск идёт по своей базе.

Обход намеренно неспешный: пауза между группами, старт через пять минут
после запуска бота. Триста сорок шесть запросов подряд к чужому сайту —
это то, за что банят, а расписание на семестр меняется редко.

Таблица пересобирается **одной транзакцией**: если сайт отвалится на
середине, лучше оставить вчерашний полный индекс, чем половину
сегодняшнего. Проверка на это есть в `test_admin`.

Лекция потока в расписании записана отдельной строкой для каждой группы —
при показе они схлопываются в одну пару со списком групп (`_slots()`).
Без этого день преподавателя выглядел бы вчетверо длиннее, чем он есть.

## ОРИОКС

Домашние задания в ОРИОКС живут не отдельной сущностью, а контрольными
мероприятиями дисциплины: `name`, `type` («Домашнее задание»,
«Лабораторная»), `week` — учебная неделя сдачи, `max_grade` и
`current_grade` (`-1` значит «не сдано»). Текста задания и файлов
API не отдаёт вовсе — экран честно отвечает «что и когда сдавать», а не
заменяет ОРИОКС.

**Пароль не хранится нигде.** ОРИОКС меняет логин с паролем на токен
(`GET /api/v1/auth`, Basic-авторизация), в базу (`orioks_links`)
ложится только токен. Пароль проходит через сервер один раз и не
записывается — на это есть проверка, которая перебирает ВСЕ таблицы и
столбцы базы и ищет там пароль. Если будешь трогать этот код, не сломай
её: она единственное, что стоит между «удобно» и «утекли чужие учебные
аккаунты».

**Чужие задания недоступны никому**, включая владельца: в ОРИОКС ходим
под токеном того, кто спрашивает. `see_all` тут не работает и работать
не должен.

**ОРИОКС виден не отовсюду.** С адресов вне России он рвёт TLS — та же
защита, что у miet.ru. С Amvera доступен (проверено маршрутом
`/api/admin/orioks-probe`), с машины автора — нет, поэтому проверки
подменяют `orioks._request` и в сеть не ходят.

**Неделю в дату превращает клиент**, а не сервер: начало семестра
считается из расписания (`semesterStart`), и второй расчёт на сервере
означал бы два разных ответа на один вопрос.

## Мини-приложение

**Вкладок ровно четыре**: Главная, Расписание, Лента, Полезное. Пятая
подпись в нижней панели уже жмётся, поэтому кружки и профиль переехали
внутрь «Полезного» — туда заходят по делу, а не постоянно. Профиль
остался в одно нажатие с главной (иконка в шапке).

«Полезное» (`screens/useful.js`) — оглавление плитками, сгруппированное
по тому, как часто спрашивают: сначала «кто ведёт и где», потом баллы,
потом справочное. Цвет плитки закреплён за смыслом (учёба синяя,
справочное зелёное, деньги и жильё тёплые, инструменты фиолетовые) —
одинаковые не различались бы, пёстрые превратили бы экран в ёлку.

**Ссылки в коде проверяются отдельно.** Каталог из `data/app.json`
проверяет `links_probe.py`, а адреса, записанные прямо в экранах
(официальные каналы, справочник первокурсника, контакты студсовета),
не проверял никто — такие ссылки тихо умирают. Для них есть
`tools/check_links.py`; в обычный набор проверок он не входит, потому
что трогает чужие сайты. Гонять перед выкладкой, если правил эти экраны.

Там же список `UNVERIFIABLE`: ОРИОКС и личный кабинет рвут TLS с
внешних адресов — та же защита, из-за которой miet.ru молчит через VPN.
Считать их мёртвыми нельзя, иначе проверка станет вечно красной и её
перестанут запускать.

**Про чаты и кураторов ничего не выдумано.** Каждая ссылка открыта
руками, у телеграм-каналов сверено описание (оба заявляют себя
официальными), сведения о кураторах взяты со справочника первокурсника
и страницы студсовета. Личных контактов кураторов в приложении нет —
их нет и в источниках.

**Чего в справочных экранах нет намеренно.** Оценок из ОРИОКС: доступа к
чужому личному кабинету у приложения нет и быть не должно, поэтому
калькулятор БРС считает по тем баллам, которые человек ввёл сам. Точных
дат сессии: их каждый год объявляет университет, и выдуманная дата хуже
её отсутствия — вместо неё ссылка на официальный график.

**Эмодзи в интерфейсе не используются.** Они разные на разных телефонах и
ломают ровный вид списков. Всё рисуется SVG из `js/icons.js` (стиль
Lucide, обводка 1.75). Иконка каждой сущности проставляется при сборке
данных в `tools/icons_map.py` — добавил кружок или ссылку, добавь и
иконку. В боте эмодзи остались: там они запасной вариант для премиум-икон.

Дизайн — стиль «си» (see.tg): фон страницы `#EEF0F5`, а не белый; карточки
24px; кнопки и вкладки — pill; одна почти незаметная тень; шрифт Manrope,
почти весь текст жирнее привычного. Токены — в `css/tokens.css`.

Сборки нет: ES-модули грузятся браузером напрямую. Правку видно после
перезагрузки страницы.

## Данные

`data/app.json` собирается скриптами и лежит в репозитории — приложение
на GitHub Pages читает его как статику. Пересобрать:

```bash
python tools/update.py
```

Расписание в этот файл **не входит**: и бот, и веб берут его с
`miet.ru/schedule/data` вживую (CORS открыт), поэтому оно всегда свежее.

## Проверки

```bash
python -m bot.selftest      # логика, рендер, клавиатуры, лимиты — 50
python -m bot.test_flows    # обработчики целиком, Telegram подменён — 127
python -m bot.test_admin    # права, справочник, доска, ОРИОКС — 156
python -m bot.test_posts    # лента, комментарии, режимы — 131
```

`selftest` не падает, если `miet.ru` недоступен, — берёт последнее из кеша.
Все четыре прогона должны быть зелёными перед коммитом; счёт проверок
указан здесь и его надо обновлять вместе с правкой.

Тесты открывают свою базу через `db.reset_for_tests()` до первого запроса —
`db.conn()` запоминает соединение на поток, и переключить путь потом уже
нельзя. Забыть про это — значит прогоном затереть живую статистику.

**Клиент проверяется отдельно, и это обязательно.** Питоновские
прогоны не видят JavaScript вовсе, а один битый модуль роняет всё
приложение — граф импортов рушится целиком, человек получает белый экран:

    python tools/check_modules.py   # импорты, забытые имена, иконки, классы
    python tools/check_app.py       # выполняет модули в движке (нужен dukpy)

`check_app.py` появился после того, как приложение легло из-за двух
объявлений одного имени: `dayLabel` импортировали в модуль, где он уже
был объявлен. Ни сверка импортов, ни проверка синтаксиса по отдельным
файлам такого не видят — нужно именно выполнить сборку. Гонять обе
проверки перед каждой выкладкой клиента.

Движка JS в системе нет, поэтому `check_app.py` работает через
`dukpy` (`pip install dukpy`) с игрушечными заглушками DOM: цель не
отрисовать приложение, а дойти до конца загрузки без исключения.

`test_admin` зовёт `api.handle()` напрямую, без сокета: так проверка не
зависит ни от свободного порта, ни от системного прокси, который на машине
автора заворачивает `localhost` и отвечает 502.

## Выкладка

Мини-приложение — GitHub Pages, обновляется пушем в `origin main`.

Бот — Amvera Cloud, **пуш обязательно `main:master`**: платформа следит за
`master`, локально работа идёт в `main`.

```bash
git push amvera main:master
```

Токен только в переменных окружения панели Amvera, `.env` в `.gitignore`.
Всё, что бот пишет, должно уходить в `DATA_DIR` (в облаке `/data`) —
файлы рядом с кодом стираются при каждой выкладке. Подробности в
[DEPLOY.md](DEPLOY.md).

Две части знают друг о друге ровно в одном месте: адрес API в
`js/config.js` и переменные `ADMIN_IDS` / `ALLOW_ORIGIN` в панели Amvera.
Переехал домен бота — правится `js/config.js` и пушится в `origin main`,
иначе приложение молча останется без учёта и админки.

Частая засада: с включённым VPN `miet.ru` и `git.amvera.ru` не отвечают —
они отклоняют зарубежные адреса. TCP при этом проходит, рвётся TLS.

## Стиль

Комментарии и весь текст для пользователя — по-русски. Комментарий
объясняет, **почему** так, а не пересказывает код; если причина
неочевидна (обход ограничения Telegram, особенность данных МИЭТ) — она
должна быть записана.
