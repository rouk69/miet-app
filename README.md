# МИЭТ — Telegram-бот и мини-приложение

**Бот:** [@mietapp_bot](https://t.me/mietapp_bot) ·
**Приложение:** https://rouk69.github.io/miet-app

Две части, работающие в паре:

- **бот** — расписание в личке и в любом чате через inline-режим, с рабочими
  кнопками переключения дней и недель прямо под сообщением;
- **мини-приложение** — веб-версия внутри Telegram: расписание, новости,
  кружки, институты и кампус.
Мини-приложение оформлено в стиле **«си» (see.tg)** по дизайн-киту — светлая
воздушная iOS-эстетика, всё максимально скруглено, фон не белый.

Данные настоящие, собраны с [miet.ru](https://www.miet.ru): 60 новостей
с фотографиями, 15 институтов с контактами, 10 разделов кампуса, **28 кружков
и объединений**, 39 полезных ссылок, 346 учебных групп. **Расписание тянется
живьём** с `miet.ru/schedule/data` — эндпоинт отдаёт
`Access-Control-Allow-Origin: *`, поэтому свой бэкенд для него не нужен.

## Бот

```bash
pip install -r requirements.txt
cp .env.example .env      # и вписать туда токен
python -m bot.main
```

Токен и адрес приложения читаются из `.env` в корне проекта — файл в
`.gitignore`, в репозиторий не попадает. Можно и обычными переменными
окружения, они имеют приоритет.

**Настройка у [@BotFather](https://t.me/BotFather):**

1. `/newbot` — получить токен.
2. `/setinline` → выбрать бота → задать подсказку, например
   `группа — расписание`. **Без этого шага бот не работает в чужих чатах;
   через Bot API это не включается, только у BotFather.**
3. `/newapp` — привязать мини-приложение к адресу из `WEBAPP_URL`.

Команды, описание и кнопку меню настраивает разовый скрипт:

```bash
python -m bot.setup_bot
```

**Что умеет**

| Где | Как |
|---|---|
| Личка | `/today`, `/tomorrow`, `/week`, `/group`, `/shift`, `/support`, `/help` |
| Выбор группы | Два экрана кнопками: 32 направления → группы внутри. Нажал свою — расписание открылось сразу. Работает и во вставленной в общий чат карточке, прямо там же. Ввод названием тоже: «пин-31», «ПИН 31», «пин3» |
| `/start` | Одно сообщение: приветствие, что умеет бот, и сразу выбор направления — без второго сообщения с инструкцией |
| Любой чат | `@бот` и пробел — Telegram предложит вставить карточку расписания; `@бот ПИН-31` — конкретной группы |
| Кнопки | Шесть дней недели с датами, `◀ Неделя N ▶`, «Сегодня», «Неделя», «Группа», «Отправить в чат» — переключают день прямо в сообщении |
| Ссылка | При выборе группы бот даёт диплинк `t.me/mietapp_bot?start=…` — одногруппники настраиваются в одно нажатие |
| Мини-апп | Кнопка «Открыть приложение» в личке; бот передаёт группу через `?group=`, приложение открывается сразу на ней |

Кнопки под вставленной в чужой чат карточкой работают **у любого, кто нажмёт**:
группа зашита в `callback_data` (31 байт при лимите 64), серверная сессия не
нужна. В inline-сообщениях Telegram запрещает кнопки `web_app`, поэтому
кнопка приложения там не показывается — только в личке.

**Проверка без Telegram** — четыре сюиты, 311 проверок:

```bash
python -m bot.selftest     # 50 — единицы кода и живой API miet.ru
python -m bot.test_flows   # 127 — сценарии целиком
python -m bot.test_admin   # 75 — подпись, учёт, статистика, права
python -m bot.test_posts   # 59 — лента: видимость, опросы, реакции
```

`selftest` проверяет разбор предметов, недели цикла, реальные ответы
miet.ru, поиск групп, лимиты Telegram и состав клавиатур; в конце печатает
карточку так, как её увидит пользователь.

`test_admin` дёргает маршруты сервера напрямую, без сокета: подделанную и
просроченную подпись, учёт событий, подсчёт статистики, выдачу ролей и
блокировку — включая то, что бот заблокированному не отвечает вовсе.

`test_flows` прогоняет **настоящие обработчики** синтетическими апдейтами:
вместо Telegram — заглушка, запоминающая вызовы, вместо расписания —
фикстура, сети нет вообще. Покрыты `/start` с диплинком и без, выбор группы
текстом и кнопкой, все команды, переключение дня и недели, правка обычного
и inline-сообщения, inline-подсказки, обрезка длинных карточек.

Именно этот тест поймал баг, который сломал бы inline сразу после
включения: в результаты подставлялась кнопка `web_app`, а Telegram
запрещает их во вставляемых сообщениях и отклоняет запрос целиком.

## Запуск

Сборки нет — это чистый HTML/CSS/JS с ES-модулями. Нужен любой статический
сервер (просто открыть `index.html` файлом не выйдет: модули и `fetch`
требуют http).

```bash
python -m http.server 8777
```

Дальше — http://127.0.0.1:8777

## Публикация мини-приложения

Сейчас развёрнуто на GitHub Pages из ветки `main`:
https://rouk69.github.io/miet-app — обновляется само при каждом push.

Подойдёт любой статический хостинг с HTTPS: Netlify, Vercel, Cloudflare
Pages. Собирать нечего, папка кладётся как есть. Адрес идёт в `WEBAPP_URL`
бота и в `/newapp` у BotFather.

Приложение статично, но с ботом всё же разговаривает: события и админка
ходят в его HTTP-API (`bot/api.py`). Адрес — единственное место, где две
части знают друг о друге, и лежит он в `js/config.js`. Без сервера
приложение работает как раньше, просто без учёта и админки.

Кто обращается к API, решает `bot/auth.py`: `validate_init_data()` сверяет
подпись Telegram HMAC на токене бота, постоянным по времени сравнением, и
отбрасывает просроченный `initData`. **Без этой проверки любой мог бы
подделать чужого пользователя**, поэтому она стоит на каждом запросе.

## Админка

Открывается из профиля и видна только тем, кому выдан доступ. Три вкладки:

**Статистика.** Всего людей, активные сегодня и за неделю, подписки на
расписание, сколько пришло из приложения и сколько из бота, Premium,
заблокированные. Ниже — графики по дням (заходы, новые люди, обращения к
боту), разбивка «какие разделы смотрят» с долями, экраны внутри разделов,
популярные группы и что нажимают в боте.

**Юзеры.** Все, кто хоть раз открывал приложение или писал боту, свежие
сверху, с поиском по имени, нику, группе и id. По тапу — карточка: счётчики,
полоса активности за 30 дней, лента последних действий, блокировка.

**Роли.** Кому что выдано. Роль назначается в карточке человека: полный
админ, модератор с девятью правами по тумблерам или доступ к отдельным
разделам без самой админки.

Кто главный, задаётся переменной `ADMIN_IDS` — списком числовых id через
запятую (свой можно узнать у @userinfobot). Пока она пуста, админку не
видит никто: роли раздаются изнутри, а первый ключ взять больше неоткуда.
Владельца из этого списка нельзя ни разжаловать, ни заблокировать из
интерфейса — иначе одним тапом можно закрыть себе единственный вход.

Проверяет права только сервер. Кнопка в профиле спрятана от посторонних,
но это удобство: маршрут можно открыть и руками, поэтому каждый запрос
админки проверяется заново.

В учёт идут идентификатор человека, открытая часть его профиля Telegram и
названия разделов. Тексты сообщений, поисковые запросы и параметры экранов
(какая именно новость или кружок) не записываются.

## Лента и посты

Вкладка «Новости» — живая лента: посты, написанные людьми, и свежие
новости, которые бот сам забирает с miet.ru раз в три часа. Архив,
собранный скриптами в `data/app.json`, лежит там же отдельной кнопкой.

**Кто может писать.** Право `posts_write` выдаётся в админке, в карточке
человека. Пост можно написать из приложения (кнопка «Написать» — текст,
картинка, опрос, аудитория) или из бота командой `/post` — текст,
следом при желании фотография, и кнопки «Опубликовать / Анонимно /
Отмена».

**Кому видно.** По умолчанию всем. Можно выбрать группы — тогда пост
увидят только их студенты, и не только в интерфейсе: сервер не отдаст
такой пост чужому даже по прямой ссылке.

**Подпись.** Пост подписывается должностью автора — «Владелец», «Админ»,
«Модератор», «Студент», — а не именем. Новости с сайта подписаны «МИЭТ».

**Анонимные посты** ждут одобрения: они попадают в очередь, о которой
бот сообщает владельцу, и появляются в ленте после разрешения. Право
`posts_anon` позволяет публиковать анонимно сразу — без очереди.
Настоящего автора анонимного поста видит только тот, кто разбирает
очередь; наружу он не отдаётся.

**Опрос** — до шести вариантов, голос один на человека, переголосовать
можно. **Реакции** — 👍 ❤️ 🔥 😂 😮, тоже по одной на человека, повторный
тап снимает. **Прочтения** считают людей, а не открытия.

**Длинные записи свёрнуты** до четырёх строк, полный текст раскрывается
кнопкой «Подробнее» на месте — новость с сайта это несколько тысяч
знаков, и развёрнутой она превращает ленту в простыню. Текст при этом
лежит в разметке целиком, так что раскрытие мгновенное. Четыре свежие
записи показываются и на главной; пока сервер не ответил, там остаётся
архив из `data/app.json`, чтобы блок не был пустым.

## Обновление данных

Новости и справочная информация лежат статикой в `data/app.json` — их надо
пересобирать. Расписание обновлять не нужно, оно живое.

```bash
pip install requests beautifulsoup4 pillow
python tools/update.py
```

Займёт 12–15 минут: `harvest.py` собирает новости, институты и разделы,
`clubs.py` — секции при ДК и спорткомплексе, `student_clubs.py` — студенческие
сообщества, `build_data.py` сжимает фотографии (до 1100 px, JPEG q80) и
собирает итоговый `data/app.json`. Отдельно `links_probe.py` проверяет, что
все ссылки в каталоге ещё живы.

## Что стоит знать

**Расписание не «заканчивается» через четыре недели.** miet.ru отдаёт не
окно из четырёх недель, а повторяющийся шаблон цикла на весь семестр:
в ответе API вообще нет календарных дат — только `Day` (1–6) и `DayNumber`
(0–3, неделя цикла). Дату считаем сами от начала семестра, поэтому цикл
крутится сколько угодно и продлевать нечего.

Смену семестра ловим по полю `Semestr`: когда МИЭТ опубликует весеннее
расписание, строка изменится, отсчёт пойдёт с 9 февраля, а кеш подтянет
новые данные в течение суток.

**Поправка недели живёт только внутри своего семестра.** Цикл в новом
семестре начинается заново, и сдвиг, выставленный осенью, весной почти
наверняка окажется другим. Молча применять старый нельзя — человек увидел
бы не ту неделю и не понял почему, поэтому при смене семестра поправка
обнуляется (`storage.shift_for`).

**Тема.** Светлая и тёмная переключаются вручную в профиле и за темой
Telegram не следуют — так задумано в дизайн-ките: компоненты про тему
ничего не знают, меняются только значения CSS-переменных.

**Кеш расписания.** В приложении ответ API кладётся в `localStorage` на
сутки, в боте — на диск на 6 часов. Кнопка обновления в шапке расписания и
пункт в профиле сбрасывают его принудительно.

**Через VPN связь рвётся, и это лечится повторами.** Соединение с
`api.telegram.org` обрывается раз в несколько минут. Опрос от этого
восстанавливается сам, а вот отправка ответа — нет: запрос падал с
`ConnectionError`, обработчик умирал, и человек не получал ничего на свою
команду. Поэтому включены встроенные повторы `apihelper.RETRY_ON_ERROR` —
они охватывают все вызовы Bot API, включая отправку. Плюс `/start` ловит и
сетевые ошибки, откатываясь на простое сообщение.

Трейсбеки обрывов сворачивает в строку фильтр `ShortNetworkErrors`: без
него за час набегает треть мегабайта лога. На сервере без прокси ничего
этого не происходит.

**Команды работают только там, где бот есть.** `/start` и остальные —
в личке с ботом или в группе, куда он добавлен. Inline-режим (`@mietapp_bot`)
работает в любом чате, даже там, где бота нет: это разные механизмы
Telegram, и одно без другого — норма.

**Где живёт список кружков.** Каталог студенческих сообществ лежит не в
структуре сайта, а на портале «Студенту» — `miet.ru/page/113391`. В общем
меню его нет, поэтому `student_clubs.py` берёт список именно оттуда:
вычитает из ссылок индекса ссылки обычной страницы и получает ровно
сообщества, без захардкоженных id.

**Три ссылки на сайте не работают.** `/sport/`, `/dk/` и `/contacts/`
отдают 404 — в каталоге вместо них стоят реальные страницы этих
подразделений (`/structure/s/355`, `/structure/s/354`, `/page/1127`).
Разделы `/education/`, `/education/programs/`, `/education/documents/` и
`/special/entrant` отдают только каркас сайта без содержимого, поэтому
в каталоге заменены на страницы с реальными данными.

**Диплинк на группу кодируется.** В start-параметр Telegram пускает только
`[A-Za-z0-9_-]`, а все группы МИЭТ кириллические — «ПИН-31» ссылкой не
передать. Поэтому там base64url: `?start=0J_QmNCdLTMx`, 12 символов при
лимите 64.

**Премиум-эмодзи показываются не всем.** Иконки в карточке — кастомные
эмодзи из паков SFSymbols и CircleNumbers. По документации Bot API их
разрешено слать либо ботам с именем, купленным на Fragment, либо в личку и
группы, если владелец бота — Telegram Premium. Заранее это не проверить,
поэтому бот пробует и запоминает отказ: `with_emoji_fallback` один раз
получает ошибку и дальше шлёт обычные эмодзи. У каждой иконки указан
запасной — 📖 для лекции, 👤 для преподавателя, 📍 для аудитории, — так что
без премиума карточка не разваливается, а просто становится проще.

**Карточка — настоящая таблица.** С Bot API 10.1 появились rich-сообщения:
`sendRichMessage` принимает разметку «Rich HTML style», где есть
`<table bordered compact>`, `<td align valign colspan rowspan>`, заголовки
и — главное — кнопки прямо в теле сообщения: `<tg-button-row>` с
`<tg-button type="callback_data|url|web_app|switch_inline_query|disabled"
style="primary|success|danger|link">`. Отсюда и рамки, и вертикальное
выравнивание номера пары, и цветные кнопки. Правится это через
`editMessageText` с полем `rich_message`, так что переключение дня
работает как раньше.

Нужен **pyTelegramBotAPI 4.36+**: в 4.14 ничего этого ещё не было.

**Откат двухступенчатый.** Если сервер не примет rich-сообщение — бот
переходит на обычное с цитатами и клавиатурой под сообщением; если не
примет премиум-эмодзи — на обычные. Оба отказа запоминаются, чтобы не
дёргать Telegram впустую. Обычный путь работает везде, так что худший
случай — просто менее нарядная карточка.

**В интерфейсе нет эмодзи.** Они выглядят по-разному на разных телефонах
и ломают ровный вид списков, поэтому всё рисуется SVG: `js/icons.js` —
90 иконок в стиле Lucide, обводка 1.75, как требует дизайн-кит. Имя иконки
проставляется каждой сущности в `tools/icons_map.py` при сборке данных.
В боте эмодзи остались — там они запасной вариант для премиум-иконок.
