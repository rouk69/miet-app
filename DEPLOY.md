# Выкладка бота на Amvera Cloud

Мини-приложение уже работает круглосуточно — оно лежит на GitHub Pages.
Здесь только про бота: чтобы он отвечал, когда ноутбук выключен.

Всё, что нужно от репозитория, уже готово: `amvera.yml`, `main.py` в корне,
`requirements.txt`. Осталось создать проект и запушить.

---

## 1. Регистрация

Зайди на [amvera.ru](https://amvera.ru) и зарегистрируйся. Карта не нужна,
на балансе появятся стартовые деньги — боту их хватает надолго: он ест
около 60 МБ памяти и почти не грузит процессор.

## 2. Создать проект

В панели: **Проекты → Создать проект**.

| Поле | Значение |
|---|---|
| Название | `miet-bot` (любое) |
| Тип | **Приложение** |
| Тариф | самый дешёвый из доступных |

Дальше платформа предложит выбрать способ загрузки кода — выбирай **Git**.
Конфигурацию она тоже предложит сгенерировать; это пропускаем, `amvera.yml`
уже лежит в репозитории.

## 3. Переменные окружения

**Проект → Переменные** (или «Настройки → Переменные окружения»). Добавь:

| Имя | Значение |
|---|---|
| `BOT_TOKEN` | токен от @BotFather |
| `WEBAPP_URL` | `https://rouk69.github.io/miet-app` |
| `DATA_DIR` | `/data` |
| `ADMIN_IDS` | твой числовой id — узнать у @userinfobot |

`ADMIN_IDS` — ключ от админки. Пока переменная пуста, админку не видит
никто: роли раздаются изнутри неё, а взять первый ключ больше неоткуда.
Несколько владельцев пишутся через запятую. Владельца из этого списка
нельзя ни разжаловать, ни заблокировать из интерфейса — иначе можно было
бы одним тапом закрыть себе вход.

`BOT_TOKEN` задаётся только здесь. Файл `.env` лежит в `.gitignore` и в
облако не уезжает — токен в репозиторий не попадает.

`DATA_DIR` важен: всё, что бот пишет не туда, стирается при следующей
выкладке. В `/data` живут база выбранных групп и кеш расписания, и они
переживают обновления.

## 4. Открыть API наружу

Бот поднимает HTTP-API для мини-приложения: через него идут учёт заходов и
вся админка. Наружу Amvera пускает только 80-й порт, и его надо включить:
**Проект → Настройки → Доменные имена** (или «Сеть») → включить внешний
домен. Получится адрес вида `https://miet-bot-rouk.amvera.io`.

Этот адрес должен совпадать с `DEFAULT_BASE` в `js/config.js`. Если он
другой — поправь файл и запушь в `origin main`, иначе приложение молча
останется без статистики и админки: сервера по записанному адресу просто
нет.

Проверить, что API живёт, можно прямо в браузере:

```
https://miet-bot-rouk.amvera.io/api/health
```

Ответ `{"ok": true}` означает, что сервер поднялся. Всё остальное требует
подписи Telegram и из браузера отвечает `401` — это норма, а не поломка.

## 5. Отправить код

В корне проекта на компьютере:

```bash
git remote add amvera https://git.amvera.ru/ТВОЙ_ЛОГИН/miet-bot
```

```bash
git push amvera main:master
```

Логин и пароль — те же, что от личного кабинета Amvera. Пуш запускает
сборку автоматически.

Двоеточие в команде обязательно. Amvera следит только за веткой `master`,
а локально работа идёт в `main`: `main:master` отправляет её содержимое
под тем именем, которое ждёт облако. Если запушить просто `main`, объекты
доедут, но платформа коммита не увидит — проект останется со статусом
«Не развертывался», а панель будет отдавать
`500: Git client returned 500 on route: .../commit/last`.

## 6. Выключить локального бота

**Это обязательно.** Telegram отдаёт обновления только одному
получателю: если бот работает и на ноутбуке, и в облаке, они начнут
отбирать сообщения друг у друга, и оба будут падать с ошибкой
`409 Conflict`.

Закрой окно с локальным ботом или сними задачу:

```bash
taskkill /F /IM python.exe
```

## 7. Проверить

В панели открой **Логи**. При нормальном старте там появится:

```
API слушает порт 80
Бот @mietapp_bot запущен
Мини-приложение: https://rouk69.github.io/miet-app
```

Если вместо первой строки — предупреждение «API не поднялся на порту 80»,
порт занят: бот при этом работает, а статистика и админка нет.

Предупреждение «ADMIN_IDS не задан — админка не откроется никому» означает,
что переменная из шага 3 не сохранилась или проект не перезапущен.

Напиши боту `/start` — ответ должен прийти. Выключи ноутбук и напиши ещё
раз: теперь отвечает облако.

## Обновления

Каждый раз, когда меняешь код:

```bash
git push amvera main:master
```

Пересборка занимает пару минут. Выбранные группы пользователей и кеш
никуда не денутся — они в `/data`.

Обновить данные приложения (новости, кружки, фото) — отдельная история,
это `python tools/update.py` и пуш в GitHub, к боту отношения не имеет.

## Если что-то пошло не так

**Сборка падает на установке зависимостей.** Проверь, что `requirements.txt`
лежит в корне репозитория, а не в `bot/`.

**В логах `409 Conflict`.** Где-то работает второй экземпляр бота — почти
всегда локальный, см. шаг 6.

**В логах `Не задан BOT_TOKEN`.** Переменная не сохранилась в панели или
проект не перезапущен после её добавления. Отметка «секрет» при вводе
токена ничему не мешает: в контейнер такая переменная приходит как
обычная, просто её значение больше не показывается в панели.

**Статус «Не развертывался», лог сборки пустой.** Код ушёл не в ту ветку.
Проверь, что в команде пуша есть `main:master` — см. шаг 5.

**Бот молчит, логи пустые.** Проект остановлен или закончились деньги на
балансе — посмотри статус в панели.

**Расписание не грузится, в логах ошибки сети.** Сайт МИЭТ недоступен;
бот отдаст последнее из кеша и попробует снова.

**Админки нет в профиле, статистика пустая.** Приложение не достучалось до
API. Открой `https://miet-bot-rouk.amvera.io/api/health`: нет ответа —
внешний домен не включён (шаг 4) или проект остановлен; ответ есть, а
админки нет — адрес в `js/config.js` не совпадает с доменом, либо твой id
не попал в `ADMIN_IDS`.

**В приложении админка есть, а цифры нулевые.** События копятся пачками и
уходят при уходе с экрана — загляни через минуту пользования. Совсем ноль
означает, что запросы не доходят: смотри `/api/health` выше.
